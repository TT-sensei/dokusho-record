# 読書レコード

読んだ本を、自分の本棚に積み重ねていく読書記録Webアプリです。
GitHub Pagesで動作する静的サイト（HTML / CSS / JavaScript）で、タブレットでの利用を主軸にしています。

冊数やランキングを主役にせず、表紙が並ぶ「本棚」そのものを中心にしています。

## 公開URL

https://tt-sensei.github.io/dokusho-record/

## 画面構成

- 本棚：表紙のグリッド、検索・絞り込み、控えめな冊数表示
- 本を登録：ISBNで探す / 表紙を撮る / 写真から選ぶ
- 設定：目標設定、JSONバックアップ・復元

将来的に、バッジやナビキャラクターなどの機能を追加する予定です。現段階では本棚・登録・設定をシンプルに保ちます。

## データ保存

書誌情報・読書記録はlocalStorage、ユーザーが撮影・選択した表紙画像はIndexedDBに保存します。
ISBN検索で取得した表紙はURLのみを保存し、画像そのものをIndexedDBへ複製しません。端末で撮影・選択した表紙だけを縮小・圧縮してIndexedDBへ保存します。

サーバーへの送信、ログイン、ユーザー登録、学校単位の集計は行いません。

## ISBN検索

ISBN検索では、Google Books API、openBD、NDLサーチの3ソースを並行取得し、取得できた情報を補完して1件の書誌情報にまとめます。

- Google Books：タイトル、著者、ページ数、価格、表紙URL
- openBD：タイトル、著者、ページ数、価格、表紙URL
- NDLサーチ：タイトル、著者、説明・extentからのページ数、価格情報、書影URLの補完

3ソースのうち一部が失敗しても、残りの結果で登録を続行できます。全ソースから情報を取得できない場合は手入力へ切り替えられます。

NDLサーチAPIを利用していることが分かるよう、今後の画面構成に合わせて適切なクレジット表示を行います。

## 表紙について

ISBN検索で取得した表紙はURLを保存します。ユーザーが「表紙を撮る」「写真から選ぶ」で登録した画像はIndexedDBへ保存します。

ユーザー画像は長辺900px程度に縮小し、JPEGとして圧縮して保存します。元の写真アプリ側の画像を削除しても、アプリ内に保存した表紙は残ります。

## バーコードと表紙撮影

ISBN取得用のバーコードスキャンと、表紙画像の撮影・選択は別機能として実装しています。

- `barcode.js`：QuaggaJSによるEAN-13（ISBN）検出
- `camera.js`：表紙撮影・端末写真の選択
- `imagestore.js`：IndexedDBへの表紙保存

バーコードが使えない場合でも、ISBN手入力や表紙撮影から登録できます。

## 目標

年間・月間の読書目標を設定できます。目標は本棚上部に控えめに表示し、達成時だけ短いメッセージを表示します。ランキングや競争を促す仕組みは入れていません。

## バックアップ

設定画面からJSON形式でバックアップ・復元ができます。

通常は書誌情報のみを書き出し、「撮影した表紙画像も含める」を選択した場合だけIndexedDBの画像をJSONへ同梱します。

## オフライン

アプリ本体はService Workerでキャッシュされ、本棚の閲覧・検索・お気に入り・編集・削除・目標設定・バックアップなどはオフラインでも利用できます。

ISBN検索にはインターネット接続が必要です。

## 開発方針

- GitHub Pagesでそのまま動作する静的構成
- APIキー不要の無料サービスを優先
- サーバー・データベースを使わず端末内で完結
- 子どもが使う画面では、記録そのものを主役にする
- バッジやナビキャラクターは本棚・登録機能を壊さない形で後から追加する

## 動作確認

Node.js上でJavaScriptの構文、ISBN処理、localStorageデータのマイグレーション、ISBN検索のテキスト処理、HTMLと実ファイルのパス整合性などを確認しています。

カメラ、バーコードスキャン、IndexedDB、Service Workerは実際のタブレット・ブラウザでも確認してください。
