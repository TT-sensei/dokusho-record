# 読書レコード

GitHub Pages上で動作する、児童向けの個人読書記録Webアプリです。

**集約しない・ログインしない・端末内で完結する**を最優先の設計方針とし、
学校やクラス全体でのデータ集約機能は一切実装していません。児童が自分の
端末で、自分が読んだ本を記録し、年間・月間の読書目標を確認し、冊数に
応じてバッジを獲得できます。

## 公開URL(GitHub Pagesにデプロイ後)

```
https://tt-sensei.github.io/reading-record/
```

## 使い方(セットアップ)

1. このフォルダの中身をリポジトリ `TT-sensei/reading-record` の直下に配置する。
2. GitHubのリポジトリ設定でGitHub Pagesを有効化する(`main`ブランチ / ルート)。
3. 数分後に上記URLでアクセスできる。ビルド工程は不要(素のHTML/CSS/JS)。
4. スマートフォンでアクセス後、「ホーム画面に追加」でPWAとしてインストールできる
  (インストールしなくても通常のWebページとして完全に利用できる)。

## 画面構成

| 画面 | 内容 |
| --- | --- |
| ホーム | 今年の冊数・進捗バー・今月の状況・連続記録・バッジ数・登録ボタン |
| 本を登録 | バーコード読み取り / 手入力の2方式 |
| 読書記録 | 登録済みの本の一覧・検索・詳細・削除 |
| 集計 | 年間集計・月別集計(棒グラフ) |
| バッジ | 獲得済み/未獲得バッジの一覧 |
| 目標・設定 | 年間/月間目標の変更、JSONバックアップ・復元 |

## データの扱い

- 読書記録はすべて **その端末のブラウザのlocalStorageのみ** に保存されます。
- サーバーへの送信、ログイン、ユーザー登録、クラス/学校単位の集計は
  一切行いません。
- ブラウザデータの削除や機種変更に備え、設定画面から
  **JSON形式でのバックアップ・復元** が可能です(必須機能として実装済み)。
- 外部通信が発生するのは、ISBNから書籍情報を検索するとき
  (openBD → Google Books API)と、バッジ/ナビキャラの画像を表示するとき
  のみです。どちらも失敗してもアプリ本体(記録・集計・バッジ確認など)は
  問題なく動作します。

### データ構造(localStorage: `reading-record:v1`)

```jsonc
{
  "version": "1.0",
  "settings": { "annualTarget": 50, "monthlyTarget": 5 },
  "stats": { "currentStreak": 3, "longestStreak": 7, "lastReadDate": "2026-09-09" },
  "badges": ["step1", "beginner"],
  "books": [
    {
      "id": "9784001140019_abc123_x9z1q",
      "isbn": "9784001140019",
      "title": "本のタイトル",
      "author": "著者名",
      "publisher": "出版社",
      "coverUrl": "",
      "readDate": "2026-09-09",
      "memo": "おもしろかった!",
      "entryMethod": "barcode",
      "isFavorite": false,
      "genre": "",
      "isReread": false,
      "createdAt": "2026-09-09T01:23:45.000Z"
    }
  ]
}
```

> 仕様書のサンプルでは `id` にISBNをそのまま使っていましたが、同じ本を
> 「再読」として複数回記録できるようにするため、`id`は常に一意な文字列を
> 生成し、`isbn`は別フィールドとして持たせています。重複判定や集計は
> `isbn`/`title`側で行うため、動作・データ構造の考え方に変更はありません。

`js/storage.js` の `migrate()` が、古い/壊れたデータでも安全な形に
補正してから読み込むため、将来のバージョンアップにも対応できます。

## 重複本の扱い

- バーコード登録は **ISBN** を優先して重複判定します。
- 手入力は **タイトルを正規化(NFKC正規化・前後空白/内部空白除去・大小文字統一)して完全一致** で判定します(曖昧一致による誤検知を避けるため)。
- 重複が見つかった場合はエラーにせず、「この本、前にも読んでいるよ!」と
  前向きに表示し、「別の本を探す」「もう一度読んだ」を選べます。
- 「もう一度読んだ」を選ぶと `isReread: true` として記録されますが、
  通常の読書冊数(年間/月間集計・バッジ判定)には二重計上されません。

## バッジ

冊数に応じて自動獲得します(`js/badges.js`)。一度獲得したバッジは、
本を削除して冊数が減っても取り消されません(獲得記録は永続、判定条件は
常に読書記録から再計算できる設計)。

| 冊数 | バッジ名 |
| --- | --- |
| 1 | はじめの一歩 |
| 5 | 読書ビギナー |
| 10 | 読書チャレンジャー |
| 20 | 読書マスター |
| 30 | 読書ハンター |
| 50 | 50冊達成! |
| 100 | 読書レジェンド |

バッジ獲得時・年間/月間目標達成時は、簡易紙吹雪(`canvas-confetti`を
優先使用し、読み込めない場合は自作の軽量フォールバックに自動切替)付きの
演出を表示します。

## 既存資産(edu-kit / navi-character- / edu-assets)との接続

実装前に各リポジトリの実ファイル(`catalog.json` / `AI-GUIDE.md` /
`assets/web/` 以下)を確認し、実在するパスのみを使用しています。

- **バッジ画像**: `edu-assets` の軽量WebP
  (`assets/web/badges/common/{icon}/badge.webp`)を直接参照
  (`js/badges.js`)。
- **ナビキャラ**: `navi-character-` の軽量WebP
  (`assets/web/characters/{id}/fullbody/{pose}.webp`)を直接参照
  (`js/navi.js`)。役割はnavi-character-のAI-GUIDEにある役割表に準拠
  (そら=登録、なみ=重複・再読、つき=目標達成、さく=バッジ獲得、
  かい=ヒント・見つからない場合)。
- どちらも **このリポジトリへ画像を複製していません**
  (各AI-GUIDEの「複製せず公開URLを参照する」という指示に従っています。
  詳細は `assets/badges/README.md` / `assets/characters/README.md`)。
- 画像が読み込めない場合(オフライン・障害時)は、`onerror`で吹き出し/
  バッジ表示が自動的に非表示・絵文字フォールバックになり、
  アプリ本体の動作(登録・記録・集計・削除・バックアップなど)は
  一切妨げられません。
- `edu-kit`(共通デザインの起点)は、その中心資産である
  `edu-components` / `edu-effects` が状態管理・演出をDOM/CSSに深く
  結びつける前提の共通基盤であるのに対し、本アプリは
  「集約しない・ログインしない・端末内で完結する」という要件上、
  独立した最小構成のlocalStorage実装が適していると判断し、
  ロジック・CSSは単独実装としました。配色はedu-kitの世界観
  (紙色の背景・落ち着いたインク色・複数のアクセントカラー)を
  参考にしつつ、本アプリ独自の「図書館の灯り」トーンで再構成しています
  (外部CSSへの依存を作らないことで、単独でも確実に動作させるため)。

## オフラインでの動作

- 本体のHTML/CSS/JS/アイコンはService Worker (`sw.js`)でキャッシュし、
  電波が悪い/オフラインでも起動・閲覧・記録・集計・バッジ確認・目標設定・
  バックアップ書き出しが可能です。
- ISBN検索(openBD/Google Books)はネットワークが必須です。接続できない
  場合は「本の情報を見つけられませんでした」と表示し、手入力へ誘導します
  (登録処理全体が止まることはありません)。
