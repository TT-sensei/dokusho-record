# マガジンラック(読書レコード v2)

「読んだ本が、自分のマガジンラックに増えていく」読書記録Webアプリです。
GitHub Pagesで動作する静的サイト(HTML/CSS/JS)で、**タブレットでの利用を主軸**に設計しています。

冊数や集計を主役にせず、**表紙が並ぶ本棚そのものを主役**にしています。

## 公開URL(GitHub Pagesにデプロイ後)

```
https://tt-sensei.github.io/reading-record/
```

## セットアップ

1. このフォルダの中身をリポジトリ `TT-sensei/reading-record` の直下に配置する
  (既存の内容を上書きします。v1からのコンセプト変更に伴う全面刷新です)。
2. GitHub Pagesを有効化する(`main`ブランチ / ルート)。ビルド工程は不要。
3. タブレットでアクセス後、「ホーム画面に追加」でPWAとしてインストールできる
  (インストールしなくても通常のWebページとして完全に利用できる)。

## 画面構成

| 画面 | 内容 |
| --- | --- |
| 本棚 | 表紙のグリッド表示(主役)、検索・絞り込み、控えめな冊数表示 |
| 本を登録 | 「ISBNで探す」「表紙を撮る」「写真から選ぶ」の3方式 |
| 設定 | 目標設定、JSONバックアップ・復元 |

タブレット(700px以上)ではナビゲーションが**左レール**に、スマートフォンでは
**下部タブ**になります(左レールはタブレットの横幅を活かした本アプリの
基本ナビゲーション形式です)。

## データの保存方式

| データ種別 | 保存先 |
| --- | --- |
| 書誌情報・記録(タイトル、著者、ISBN、ページ数、価格、読了日、感想、お気に入り、目標、**表紙のURL**) | localStorage |
| ユーザーが撮影・選択した表紙画像そのもの | IndexedDB |

- ISBN検索で取得した表紙は「URLのみ」をlocalStorageに保存し、画像そのものは
  複製・保存しません(URLが後日無効化された場合は、表紙表示部分だけが
  プレースホルダーに切り替わり、そこから「表紙を撮る」で登録し直せます)。
- カメラ撮影・端末の写真から選んだ表紙だけを、長辺900px・JPEG品質0.75に
  縮小・圧縮してIndexedDBへ保存します(`js/imagestore.js`)。元の写真アプリ側の
  画像を消しても、アプリ内の表紙は残ります。
- サーバーへの送信、ログイン、ユーザー登録、学校単位の集計は一切行いません。

### localStorageのデータ構造(`magazine-rack:v2`)

```jsonc
{
  "version": "2.0",
  "settings": { "annualTarget": 50, "monthlyTarget": 5 },
  "books": [
    {
      "id": "9784001140019_abc123_x9z1q",
      "isbn": "9784001140019",
      "title": "本のタイトル",
      "author": "著者名",
      "pageCount": 236,
      "price": 1200,
      "coverSource": "api",       // 'api' | 'user' | 'none'
      "coverUrl": "https://...",   // coverSource === 'api' のとき
      "coverImageId": "",          // coverSource === 'user' のとき(IndexedDBのキー)
      "registeredDate": "2026-09-09",
      "readDate": "2026-09-09",
      "memo": "おもしろかった!",
      "isFavorite": false,
      "entryMethod": "isbn",       // 'isbn' | 'photo' | 'library' | 'manual'
      "createdAt": "2026-09-09T01:23:45.000Z"
    }
  ]
}
```

`js/storage.js` の `migrate()` が壊れた/想定外のデータでも安全な形に補正して
読み込むため、将来のバージョンアップにも対応できます。

## 同じ本を複数回登録することについて

v2では**重複登録のブロックを行いません**。「読んだ本が並んでいく本棚」という
コンセプト上、同じ本を再読して改めて記録することも、本棚にもう一冊(もう一度)
並べる自然な行為として扱っています。

## ISBN検索(3ソース統合)

1つのAPIに依存せず、`Promise.allSettled`で以下を並行取得し、互いの欠けを
補い合います(`js/isbn-search.js`)。すべて無料・APIキー不要です。

| ソース | 取得する項目 |
| --- | --- |
| Google Books API | タイトル・著者・ページ数・価格(取得できれば)・**表紙URL** |
| openBD | タイトル・著者・ページ数(ONIXのExtent含む)・価格・**表紙URL** |
| NDLサーチ(国立国会図書館) | タイトル・説明文/extentからのページ数抽出・価格 |

**マージ方針**
- タイトル・著者・表紙URL: 最初に見つかった値を採用
- ページ数・価格: 全ソースの候補から**最大値**を採用(本文+あとがき等を含む
  値が反映されやすいため)
- 著者名は年号・「著/編/訳/監修」等の付随語を除去して整形
- 見つからなかった項目(ページ数・価格など)は入力欄を赤枠で表示し、
  手入力を促す

> 表紙URLの取得は今回のアプリのために新たに追加したロジックです
> (書誌情報の合成方法は、ページ数・価格の推定を含めて
> [koitea265-blip/dokusyo_tyokinbako](https://github.com/koitea265-blip/dokusyo_tyokinbako)
> の実装を参考にしています)。

NDLサーチはCORSの都合等で取得できないことがありますが、その場合も
Google Books・openBDの結果だけで処理を継続します(全滅した場合のみ
「本の情報が見つからなかったよ」と表示し、手入力に切り替えられます)。

## バーコードスキャンと表紙撮影は別機能

- **バーコードスキャン(ISBN取得用)**: `js/barcode.js` が QuaggaJS
  (`ean_reader`)を使ってカメラ映像からISBN(EAN-13)を検出します。
  ネイティブの`BarcodeDetector`は環境によって未対応のため、互換性を優先して
  QuaggaJSを採用しています。検出後は自動的にISBN検索へ進みます。
- **表紙撮影・写真選択(画像保存用)**: `js/camera.js` が
  `<input type="file" accept="image/*" capture="environment">`
  (表紙を撮る)/ `<input type="file" accept="image/*">`(写真から選ぶ)を
  使って画像ファイルを取得します。取得した画像は`js/imagestore.js`で
  縮小・圧縮してIndexedDBに保存します。

この2つはUI・実装ファイルとも明確に分離しており、どちらか一方が使えない
環境でも、もう一方(または手入力)で登録を完了できます。

## 目標・達成表示

年間/月間の目標は本棚画面の上部に控えめな一行として表示するだけで、
主役にはしません。目標を達成した瞬間だけ、派手な演出なしの短いメッセージ
(「今月の目標を達成したよ」)を表示します。ランキングや競争を煽る要素は
意図的に入れていません。

## バックアップ・復元

- 設定画面からJSON形式でバックアップの書き出し・復元ができます
  (`js/backup.js`、初期バージョンから搭載)。
- 既定では書誌情報(localStorage側)のみを書き出します。「撮影した表紙画像も
  含める」にチェックを入れると、IndexedDBの画像もBase64(dataURL)として
  同じJSONファイルに同梱します(ファイルは大きくなります)。
- 壊れたJSON・想定外の形式を読み込んでもアプリは落ちず、エラーメッセージを
  表示します。

## オフラインでの動作

- アプリ本体(HTML/CSS/JS/アイコン)はService Worker (`sw.js`)でキャッシュし、
  オフラインでも本棚の閲覧・検索・お気に入り・編集・削除・目標設定・
  バックアップ書き出しが可能です(登録済みの基本情報はネットワークが
  無くても保持されます)。
- ISBN検索(Google Books/openBD/NDL)にはインターネット接続が必要です。
  接続できない/情報が見つからない場合は「表紙を撮る」「手入力」へ誘導し、
  登録処理全体が止まることはありません。

│   └── app.js           … ルーター・状態管理・アクションの受け口

## 動作確認済みの範囲

このコンテナ環境(ブラウザなし)では、Node.js上で以下を検証しています。

- 全JSファイルの構文チェック
- ISBN-10→13変換・チェックディジット検証
- 本の追加・更新・お気に入り切替・削除、フィルタ(すべて/お気に入り/今月/今年)、
  検索(タイトル/著者/ISBN)
- 壊れたデータ・部分的なデータからの`migrate()`によるデータ復元
- ISBN検索のテキスト処理(全角数字混じりのページ数抽出、価格抽出、
  「/著」「/編」等を含む著者名の整形)
- `index.html`のscriptパスと実ファイルの整合性、`data-action`のレンダー/
  バインド対応、`manifest.json`の妥当性

実機のカメラ・バーコードスキャン・IndexedDBの動作は、実際のタブレット/
ブラウザでのご確認をお願いします(このコンテナにはカメラもブラウザも
無いため)。
